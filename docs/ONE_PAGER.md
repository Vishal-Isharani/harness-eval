# hev — one page

**Concepts.** A **Harness** is everything the team iterates on (agent, model, args, prompt prefix, and an overlay of AGENTS.md/CLAUDE.md, skills, MCP, hooks), which makes "the change" a concrete, diffable artefact. A **Task** is a frozen repo, a business request, *hidden* acceptance tests and a binary requirements rubric; it's the smallest unit that can measure "does what the business asked". A **Suite** is a set of tasks plus the team's **conventions** as checkable rules, since conventions belong to the team, not the task. A **Trial** is one isolated, fully recorded agent run; agents are non-deterministic, so one run proves nothing. The **Scorecard** keeps four separate dimensions: resolved/hidden tests, conventions, requirements, and cost. The **Verdict** is a paired, per-task comparison with confidence intervals.

**The five hardest decisions**
1. **No single quality score.** A blended number hides trade-offs ("+5% quality, +60% cost"). I kept dimensions separate and made the verdict rules explicit: any quality regression → NEGATIVE; a gain that blows the cost budget → POSITIVE_WITH_COST_TRADEOFF.
2. **Unit of analysis = task, uncertainty = hierarchical bootstrap.** Trials inside a task aren't independent evidence. Resampling tasks and then trials gives an honest CI with no distributional assumptions. The cost is wide intervals on small suites, which the report states plainly.
3. **"No change" must be provable, not assumed.** Each metric has a practical threshold. A metric counts as "no meaningful change" only if the whole CI sits inside it; otherwise it is "inconclusive". This separates "harmless" from "we don't know".
4. **Conventions graded on added lines only.** Otherwise pre-existing debt in the repo penalises every harness equally and dilutes the signal. The price is that rules are regex-level and can produce false positives.
5. **Failures are scored, never dropped. A no-op scores 0.** Excluding crashed runs flatters a flaky harness, and an agent that changes nothing would otherwise ace conventions.

**What I cut and why.** Docker sandboxing per trial (documented instead; `--dangerously-skip-permissions` needs a VM). An HTML dashboard (markdown diffs well in PRs). Automatic task mining from merged PRs (the README gives the recipe). Isolating Claude Code from the user's `~/.claude` config: this is a real confounder I note but did not solve. Codex is best-effort and unverified. Multiple-comparison correction across metrics: at 4 quality metrics I accepted the risk and chose conservative thresholds instead.

**A result I didn't trust.** The first self-test passed on the first run, and that alone made me suspicious. I rendered the good-vs-sloppy report and recomputed the numbers by hand (hidden 3/4, 5/7, 3/6 → 65%; conventions 50/17/50%). They matched, but the "What changed in the harness" section said *"No difference detected (A/A run)"* for two clearly different harnesses: the diff only looked at overlays and config, not the replayed solutions. A report that misstates *what* was evaluated undermines every number below it. I fixed the diff and reworded the message. The A/A run also showed ±17% cost noise from simulated run-to-run variance, which is why cost is only "inconclusive" there and why the default is 3 trials, not 1. I also verified the real Claude Code path with a stub binary that logs its cwd, and found that Claude Code reads CLAUDE.md, not AGENTS.md. Without a CLAUDE.md import, the candidate's conventions would have been silently ignored and the tool would have reported "no effect" for the wrong reason.
