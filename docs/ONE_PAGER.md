# hev — one page

**Concepts.** A **Harness** is everything the team iterates on: agent, model, args, prompt prefix, and an overlay of AGENTS.md/CLAUDE.md, skills, MCP and hooks. That makes "the change" a concrete, diffable artefact. A **Task** is a frozen repo, a business request, *hidden* acceptance tests and a binary requirements rubric: the smallest unit that can measure "does what the business asked". A **Suite** is a set of tasks plus the team's **conventions** as checkable rules, since conventions belong to the team, not the task. A **Trial** is one isolated, fully recorded agent run; agents are non-deterministic, so one run proves nothing. The **Scorecard** keeps four separate dimensions: tests, conventions, requirements and cost. The **Verdict** is a paired, per-task comparison with confidence intervals.

**The five hardest decisions**
1. **No single quality score.** A blended number hides trade-offs ("+5% quality, +60% cost"). Dimensions stay separate and the verdict rules are explicit: any quality regression → NEGATIVE; a gain that blows the cost budget → POSITIVE_WITH_COST_TRADEOFF.
2. **Unit of analysis = task, uncertainty = hierarchical bootstrap.** Trials inside a task aren't independent evidence. Resampling tasks, then trials, gives an honest CI without distributional assumptions. The price is wide intervals on small suites, which the report states plainly.
3. **"No change" must be proven, not assumed.** Each metric has a practical threshold. A metric counts as "no meaningful change" only if the whole CI sits inside it; otherwise it is "inconclusive". This separates "harmless" from "we don't know".
4. **Conventions graded on added lines only.** Otherwise pre-existing debt penalises every harness equally and dilutes the signal. The price is regex-level rules that can misfire, which is exactly what happened (below).
5. **Failures are scored, never dropped, and a no-op scores 0.** Excluding crashed runs flatters a flaky harness, and an agent that changes nothing would otherwise ace conventions.

**What I cut and why.** Docker sandboxing per trial (documented instead; `--dangerously-skip-permissions` needs a VM). An HTML dashboard (markdown diffs well in PRs). Automatic task mining from merged PRs (the README gives the recipe). Isolating Claude Code from the user's `~/.claude` config: a real confounder I note but did not solve. Codex is best-effort and unverified. Multiple-comparison correction across metrics: with 4 quality metrics I chose conservative thresholds instead.

**A result I didn't trust.** In my real Claude Code run, the baseline's top convention violation was `no-true-division` at `cart.py:62`. The code looked familiar: it was the repo's *original* tax line. The trial's `diff.patch` showed it removed and re-added with more indentation, so the agent had only moved it into a new block. Because git shows a moved line as removed + added, hev's "added lines only" rule, designed to stop the tool blaming a harness for old code, did exactly that. It made the baseline look worse than it was and overstated the candidate's lead on conventions. The fix is to ignore added lines that match a line removed in the same file (ignoring whitespace), then re-grade the saved diffs without re-running agents. Lesson: any time a report points at a specific line, I check that line in the diff before I believe the number.
